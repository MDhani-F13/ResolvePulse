# ResolvePulse Laravel 13 Integration Overlay

This is an integration overlay for a **fresh Laravel 13 application**. It embeds the React/Vite UI inside Laravel's `resources/` directory and serves the app from Laravel at `/`. The frontend uses same-origin `/api/v1` calls, so CORS is not needed for this single-project setup.

## 1. Back up your fresh Laravel project

Run all commands from the Laravel project root (the directory containing `artisan`). Commit or copy the project before applying the overlay.

## 2. Install API/Sanctum first

If you have not run this on the fresh app yet, run:

```bash
php artisan install:api
```

This installs Sanctum and creates its token migration. If it generates `routes/api.php`, that's fine; the overlay's API routes will replace it in the next step. Ensure the command completes successfully before continuing.

## 3. Copy overlay files

Extract this ZIP into your Laravel project root and merge folders. Allow these overlay files to be added/replaced:

- `resources/js/resolvepulse/`
- `resources/css/resolvepulse.css`
- `resources/views/resolvepulse.blade.php`
- `app/Http/Controllers/Api/`
- `app/Http/Requests/`
- `app/Models/Ticket.php`, `TicketAuditLog.php`, and `User.php`
- `app/Policies/TicketPolicy.php`
- `app/Repositories/`
- `app/Services/`
- `database/migrations/2026_10_20_000001_create_tickets_table.php`
- `database/migrations/2026_10_20_000002_create_ticket_audit_logs_table.php`
- `database/migrations/2026_10_26_000001_add_resolvepulse_fields_to_users_table.php`
- `database/seeders/`
- `routes/api.php`, `routes/web.php`
- `vite.config.js`

Keep Laravel's original `composer.json`, `.env`, `artisan`, `bootstrap/`, and default `create_users_table` migration. This overlay intentionally does not include a duplicate users-table migration.

## 4. Check Sanctum setup

Ensure `App\Models\User` uses `Laravel\Sanctum\HasApiTokens` (the overlay version does). Keep the `personal_access_tokens` migration generated by `install:api`.

## 5. Install frontend dependencies

Keep your Laravel project's existing `package.json`. From the project root run:

```bash
npm install react react-dom lucide-react motion jszip
npm install -D @vitejs/plugin-react @tailwindcss/vite tailwindcss typescript @types/react @types/react-dom
```

The supplied `vite.config.js` preserves Laravel Vite integration and adds React + Tailwind. If your project uses `vite.config.ts` instead, merge the plugin/input settings into that file rather than keeping two Vite configs.

## 6. Configure environment

In `.env`, use your normal local database settings. For the demo quick-persona controls, add:

```dotenv
RESOLVEPULSE_DEMO_MODE=true
```

This shortcut is intended only for local portfolio demonstrations. Do not enable it in a publicly exposed or production environment. Demo users are seeded with the password `password123`.

## 7. Run migrations and seed

Only if you can safely reset this development database:

```bash
php artisan migrate:fresh --seed
```

`migrate:fresh` deletes all existing tables in the configured database. If you need to preserve data, use `php artisan migrate` and seed carefully instead.

## 8. Build and run

```bash
npm install
npm run dev
```

In another terminal:

```bash
php artisan optimize:clear
php artisan serve
```

Open `http://127.0.0.1:8000`.

## Notes

- This uses same-origin API requests. You do not need CORS for React-to-Laravel requests in this arrangement.
- Public registration always creates a `customer`; it cannot grant staff/admin privileges from the browser.
- Demo persona switching is deliberately gated to local environment + `RESOLVEPULSE_DEMO_MODE=true`.
- The architecture explorer only reads a fixed allowlist of source files; it does not accept arbitrary file paths.
- The ticket policy should still be wired into role-specific authorization before any public deployment. This is a local portfolio demo integration, not a security audit or production certification.
